# 世界观 P0 人工验收清单（本地服务形态）

> 形态：DSH 只负责启动插件；界面与 API 由插件自己起的本地 HTTP 服务提供。
> 当前仓库的参考数据是 `data/worlds/大明王朝1566/`（4 公理 / 32 条目 / 5 片段）。
> 下面从「新建一个空世界」开始，覆盖完整录入闭环；也可以直接在大明世界上做第 4–10 步。
>
> **样本边界**：大明样本里的海瑞、严嵩、浙江等是 P0 单桶世界的测试数据，用来验证关系/时间/诊断，不是“人物地理应塞进世界观”的规范示范；人物、地理正式接入时应走各自系统，再通过 `requires` 等边引用世界观。

## 准备

- **构建与启动**：

  ```bash
  npm run build
  node --input-type=module -e "import { apply } from './index.js'; await apply({ effect: () => () => {} }, { dataRoot: '', port: 8787 });"
  ```

  或者把包作为 bundle 装进 DSH（入口 `index.js`，`cordis.patch.yml` 注入默认 `dataRoot: ''`），由 DSH 调用 `apply` 启动。
  然后在浏览器打开 **<http://127.0.0.1:8787>**（端口被占用时改 `port` 配置；DSH profile 当前用 8791）。启动失败会打印 `[novel] 工作台启动失败` 和实际使用的 dataRoot。
- **数据根**：默认是包根下的 `/data`。可用插件配置 `dataRoot` 覆盖，或用环境变量 `NOVEL_DATA_ROOT` 覆盖（显式配置优先，其次环境变量，最后包根）。
- **世界准备**：P0 现在有「＋ 新建世界」界面；也可以直接把目录放进 `dataRoot/worlds/<id>/`，至少要有 `world.yaml` 和 `nodes/`。

## 验收步骤

1. **启动服务**：按上面命令构建并启动，浏览器能打开服务地址，看到「小说工作台」外壳、顶部三阶段、左侧六个设定系统、顶部世界下拉框。刷新页面不会白屏。
2. **列世界 / 建世界**：世界下拉框列出 `dataRoot/worlds/` 下的目录名（按名称排序）；目录为空时主区提示「还没有世界」。点「＋ 新建世界」，填 id（如 `验收界`）、母题和历法，创建后下拉框出现并自动切过去。
3. **三步开局引导**：新世界公理为 0，首次进入「世界观 → 条目」时主区被引导页替代（标题「开始一个世界」）；此时「＋ 新建条目 / ＋ 新建公理」被禁用，不能绕过。
   - ① 母题写在 `world.yaml` 的 `theme.wound`（P0 界面不展示具体值）；
   - ② 加 3 条公理，每条填代价；故意把代价留空点「加一条公理」→ 必须显示服务端原文「公理必须付出代价（铁律一）」，且不落盘；补齐代价后计数到 `3 / 3`，主区切回正常条目列表；
   - ③ 进入任一公理编辑器，在「表现为（条目）」里选至少两个条目（目标条目正文不能为空），保存后 `/stats` 的 `manifestedAxioms` 才会变。
4. **写条目 / 挂关系**：点「＋ 新建条目」，标题改为「还脉礼」，正文写两句；在「派生自（公理）」里选一条公理，保存。刷新页面后条目仍在，关系仍在；编辑器里的「被条目引用」应列出引用它的公理（`manifests`）。
   新建公理走「＋ 新建公理」；类型、强度、生效区间、别名、代价、命题都在表单里，不需要手改 front matter。
5. **片段引用**：切到「片段」标签，点「＋ 新建片段」，正文写 `[[还脉礼]]`（可填章/场景），保存；回到条目打开「还脉礼」，编辑器底部「被片段引用」应列出该片段。
6. **删除保护**：打开一个**被片段或别的条目引用**的条目，点「删除」→ 应弹出拦截，错误区列出 `refs.fragments` / `refs.nodes`；换一个无人引用的条目再删 → 成功，列表消失。也可以直接用 HTTP 验证 409/204：

   ```bash
   curl -i -X DELETE 'http://127.0.0.1:8787/api/worlds/<worldId>/nodes/<条目 id>'
   ```

7. **认知层 / R9**：切到「认知」，新建一条 `holder=民间`、`target=皇权独断`、`confidence=0.9`、内容与命题不一致的记录，保存。切到「诊断」应出现 **R9**（info），消息点名 holder 与 hard 条目；把置信度改到 0.8 以下，或让 content 包含目标命题/标题/别名，R9 消失。删除该认知，诊断恢复。
8. **诊断清单 / 图谱**：切到「诊断」，应看到当前世界的规则问题（例如 R4 无公理支撑、R12 表现不足、R11 公理不足，或大明数据里故意的 R1）；切到「图谱」应看到 36 个节点/55 条边，点节点能进编辑器。
   在同一个 `dataRoot` 下运行 `NOVEL_DATA_ROOT="$NOVEL_DATA_ROOT" npm run check -- <worldId>`，终端打印的规则号、严重度与问题文案应与界面一致，并提示重建 `index.json`；存在 error 时退出码为 1。
9. **时间轴**：切到「时间轴」标签。区间来自 `world.yaml` 的历法端点，不再是固定 0–800：
   - 大明世界默认落在 1566 年，拖到 **1563** 应只剩 21 条，拖到 **1561** 是 36 条；
   - 没有 span 的条目视为一直存在；给一个条目在编辑器里填 `生效自/至`，刷新后确认它会按年份出现/消失。
10. **未定义专名**：在片段正文加 `[[不存在的词]]`，保存并刷新；左侧栏底部出现「未定义专名：不存在的词」。把它改成已有条目的标题或别名后，提示消失。
11. **本地建议**：打开任一已保存条目，底部「本地建议 → 审问我」应给出命题/问题/裁决建议；「填入」只改表单，不自动保存；面板明确写「规则生成，不调用模型」。
12. **持久化**：刷新页面，再重启 DSH（或杀掉本地服务重新 `apply`）后，逐项重新打开条目、片段、认知、诊断与时间轴，数据应保持一致。删掉 `$NOVEL_DATA_ROOT/worlds/<worldId>/index.json` 后跑一次 `NOVEL_DATA_ROOT="$NOVEL_DATA_ROOT" npm run check -- <worldId>`，索引会重建；打开诊断不会写索引（诊断直接建图）。

## 已知缺口

- **R9 只是文本近似**：hard + confidence > 0.8，且 belief 文本（去句读后）不包含目标命题/标题/别名；改写型、反讽型冲突会漏报，不能替代人工判读。
- **R6 只是「同名 + 时间重叠」的近似**：尚不能表达「同一事物的互斥版本」这类语义。
- **没有悬空关联 id 的诊断**：`derives` / `requires` / `manifests` 指向不存在的 id 时不会报错（UI 选择器只列现有节点，但手改 front matter 仍可能造成）。
- **R1 只检测显式登记的 `conflicts_with`**：语义互斥属 P1 的 AI 判读。
- **R2 把 `derives` 边当作「后果」**：这是 P1 的语义，P0 先用它压住误报。
- **没有鉴权 / CSRF 防护**：服务只监听 `127.0.0.1`，不要暴露到公网。
- **时间轴区间来自 `world.yaml` 的历法端点**：`end: null` 的开放纪元按 800 年兜底；若故事年份超出历法区间，先改历法。
- **没有世界重命名**：可以建/切换/删除；重命名仍要手改目录与 `world.yaml`。
- **引导页的「已达标」按 `manifests` 条数计**：`/stats` 不校验目标是否存在/正文是否为空/是否重复，重复或悬空 id 可能让引导页显示已达标而 R12 仍报警；统一语义属 P1。
- **`npm run check` 需从仓库运行**：脚本用 `tsx src/host/cli.ts`，打包后的包不含 `src/` 与 `tsx`；包内可运行编译后的 `node lib/host/cli.js <worldId>`。
- **验收套件规模小于 spec §9.1 / §9.4**：自动化验收按任务简报用 5 公理 + 6 条目，删除的是 `derives` 引用（断言 `refs.nodes`），未覆盖 20 条目 + 3 片段与「正文（片段）引用」分支；后者由步骤 5/6 手工覆盖。
- **AI 归纳/审问没有接模型**：当前「本地建议」是确定性规则生成，不是 AI；若要接模型，需要一个 OpenAI 兼容端点与 key，UI 已明确标注。
- **手改 belief 仍有盲区**：API 已拒绝 target 不存在的新记录，删节点也会把 belief 计入 409 引用保护；但直接手改 YAML 造成的悬空 target / 坏文件会被 R9/列表跳过，不产生诊断（坏文件会在服务端日志留下警告）。
