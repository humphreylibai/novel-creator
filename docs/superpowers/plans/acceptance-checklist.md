# 世界观 P0 人工验收清单（本地服务形态）

> 形态：DSH 只负责启动插件；界面与 API 由插件自己起的本地 HTTP 服务提供。
> 自带参考数据：`data/worlds/记忆之世/`（`world.yaml` + 1 条公理「记忆即燃料」）。

## 准备

- **构建与启动**：

  ```bash
  npm run build
  node --input-type=module -e "import { apply } from './index.js'; await apply({ effect: () => () => {} }, { dataRoot: '', port: 8787 });"
  ```

  或者把包作为 bundle 装进 DSH（入口 `index.js`，`cordis.patch.yml` 注入默认 `dataRoot: ''`），由 DSH 调用 `apply` 启动。
  然后在浏览器打开 **<http://127.0.0.1:8787>**（端口被占用时改 `port` 配置；启动失败会打印 `[novel] 工作台启动失败` 和实际使用的 dataRoot）。
- **数据根**：默认是包根下的 `/data`。可用插件配置 `dataRoot` 覆盖，或用环境变量 `NOVEL_DATA_ROOT` 覆盖（显式配置优先，其次环境变量，最后包根）。
- **世界准备**：P0 **没有建世界界面**，世界就是 `dataRoot/worlds/<id>/` 下的一个目录，至少要有 `world.yaml` 和 `nodes/`。最省事的做法是复制示例：

  ```bash
  export NOVEL_DATA_ROOT=$(mktemp -d)
  mkdir -p "$NOVEL_DATA_ROOT/worlds"
  cp -R data/worlds/记忆之世 "$NOVEL_DATA_ROOT/worlds/"
  ```

  复制并改目录名时，记得同步 `world.yaml` 里的 `id` / `title`。

## 验收步骤

1. **启动服务**：按上面命令构建并启动，浏览器能打开 `http://127.0.0.1:8787`，看到「小说工作台」外壳、顶部三阶段、左侧六个设定系统、顶部世界下拉框。刷新页面不会白屏。
2. **列世界**：世界下拉框列出 `dataRoot/worlds/` 下的目录名（按名称排序）；目录为空时主区提示「在 data/worlds/ 下还没有世界……」。改 `dataRoot` / `NOVEL_DATA_ROOT` 并重启后，列表跟着换。P0 没有「新建世界」按钮。
3. **三步开局引导**：示例世界只有 1 条公理，首次进入「世界观 → 条目」时主区被引导页替代（标题「开始一个世界」）。
   - ① 提示母题写在 `world.yaml` 的 `theme.wound`（P0 界面不展示具体值）；
   - ② 加 3 条公理，每条填代价；故意把代价留空点「加一条公理」→ 必须显示服务端原文「公理必须付出代价（铁律一）」，且不落盘；补齐代价后计数到 `3 / 3`，主区切回正常条目列表；
   - ③「每条公理至少两个能看见的东西」目前**只是提示**：`NodeEditor` 没有 manifests / 代价字段，需要在 `nodes/<公理>.md` 的 front matter 里手写 `manifests: [条目 id, ...]`（目标条目正文不能为空），刷新后 `/stats` 的 `manifestedAxioms` 才会变。不做这一步不阻塞流程，只是 R12 会继续报。
4. **写条目**：点「＋ 新建条目」，标题改为「还脉礼」，正文写两句，保存；刷新页面后条目仍在，`data/worlds/记忆之世/nodes/还脉礼.md` 可直接用编辑器打开阅读。`NodeEditor` 只编辑标题与正文，其他字段（`derives`、`span`、`conflicts_with` 等）要改 front matter；从界面保存不会丢掉这些字段。
5. **片段引用**：片段库没有界面，手工建 `data/worlds/记忆之世/fragments/第一章.md`，正文含 `[[还脉礼]]`（可加 `chapter: 1` 的 front matter）；刷新页面后打开「还脉礼」，编辑器底部「被片段引用」应列出 `第一章`。
6. **删除保护**：界面暂不提供删除按钮，用 HTTP 接口验证：

   ```bash
   curl -i -X DELETE 'http://127.0.0.1:8787/api/worlds/%E8%AE%B0%E5%BF%86%E4%B9%8B%E4%B8%96/nodes/<条目 id>'
   ```

   被片段或别的条目引用时必须返回 **409**，响应 JSON 的 `refs.fragments` / `refs.nodes` 列出引用处；无人引用时才返回 204，刷新后从列表消失。条目 id 显示在编辑器标题右侧。
7. **诊断清单**：切到「诊断」标签，应看到 R4（条目没有公理支撑）和 R12（公理有效表现少于 2 个）；如果当前公理不足 3 条，还会看到 R11（补满 3 条后自然消失）。
   在同一个 `dataRoot` 下运行 `npm run check -- 记忆之世`，终端打印的规则号、严重度与问题文案（含条目名称）应与界面一致，并提示重建 `index.json`；存在 error 时退出码为 1。
8. **时间轴**：切到「时间轴」标签，滑杆拖到 **612** 年，列表只保留 span 覆盖 612 年的条目；没有 span 的条目视为一直存在（所以示例数据会全部在场）。想看到筛选效果，先给两个条目在 front matter 里写 `span: { from: 412, to: 720 }` 之类，刷新后确认不在场的条目消失。
9. **未定义专名**：在片段正文加 `[[不存在的词]]`，刷新页面；左侧栏底部出现「未定义专名：不存在的词」。把它改成已有条目的标题或别名后，提示消失。
10. **持久化**：刷新页面，再重启 DSH（或杀掉本地服务重新 `apply`）后，逐项重新打开条目、片段引用、诊断与时间轴，数据应保持一致。删掉 `data/worlds/记忆之世/index.json` 后跑一次 `npm run check`，索引会重建；打开诊断不会写索引（诊断直接建图）。

## 已知缺口

- **R9（认知与硬法则冲突）未实现**：需要 `stance` 字段与置信阈值，属 P1。
- **R6 只是「同名 + 时间重叠」的近似**：尚不能表达「同一事物的互斥版本」这类语义。
- **没有悬空关联 id 的诊断**：`derives` / `requires` / `manifests` 指向不存在的 id 时不会报错。
- **没有建世界界面**：P0 只能手工放 `world.yaml`。
- **卡片墙没有单独视图**：浏览由左侧条目列表承担。
- **R1 只检测显式登记的 `conflicts_with`**：语义互斥属 P1 的 AI 判读。
- **R2 把 `derives` 边当作「后果」**：这是 P1 的语义，P0 先用它压住误报。
- **没有鉴权 / CSRF 防护**：服务只监听 `127.0.0.1`，不要暴露到公网。
- **引导页可被绕过**：公理不足 3 条时点「＋ 新建条目」会选中一个空条目，引导页不再显示，但诊断里的 R11 仍会提醒。
- **时间轴滑杆固定 0–800**：超出这个范围的年份只能改代码。
- **条目页没有删除按钮**：删除保护只能通过 HTTP 接口验证（见步骤 6）。
