# 小说创作辅助系统 · 总纲

> 日期：2026-11-23
> 状态：设计已确认（设定层五系统 + 规划层 + 表达层逐个过完），待用户评审后进入实施计划

---

## 0. 一句话

> **把世界观做成一组可以被下游系统查询、被 AI 校验的断言；让设定、地理、人物、编年史、事件、篇章结构、场景排演七层共用同一张图，任何改动都能算出它撞到了谁。**

## 1. 性质与范围

| 项 | 决定 |
|---|---|
| 形态 | **DSH 插件只作启动器**：随 DSH 加载时在本机拉起一个 HTTP 服务（默认 `127.0.0.1:8787`）；界面由这个服务自己吐网页，用户在浏览器里打开。**UI 不进入 DSH 页面** |
| 工作环境 | 浏览器里的独立页面（服务自己的地址）；界面与数据同源，不跨域 |
| AI 介入 | 走 DSH 的 agent 与工具（归纳 / 审问属 P1），不另接模型 |
| 使用者 | 作者自用；不做多用户、不做云端协作 |
| 目标 | 一套**方法论** + 一个**通用工具**，不面向某一部作品 |
| 通用性落地 | 题材无关的元模型（节点/边/强度/时间切片）+ 题材扩展包（玄幻的力量体系、写实的社会剖面） |
| 反范围膨胀纪律 | 核心模型每个字段必须能回答“谁读它 / 它阻止哪种错误”；答不出来的字段进扩展包 |

## 2. 三条贯穿性设计原则

### 2.1 一张断言图，七种前缀

七个系统**不是七个数据库**，而是同一张图上的七类节点。

```
W-  世界观（公理、条目）        E-  条目（通用）
P-  地理（区域、奇观、反常）     C-  人物 / G- 组织
V-  事件（编年史真相 + 事件系统） A-  卷 / 集 / 章
S-  场景 / 场记
B-  认知记录（belief，跨主体，holder 可以是「读者」）
```

“还脉礼”只有一条节点；地理挂区域、人物挂“他家乡有此俗”、编年史挂出现年份、正文挂 `cites`——全部是往同一条节点连边。

**这是“改稿牵一发动全身”能解决的唯一前提。**

### 2.2 既定度三级（全系统统一）

| 状态 | 含义 | 系统行为 |
|---|---|---|
| `derived` | 系统建议 | 可被重算覆盖 |
| `accepted` | 作者采纳 | 重算只提示，不改 |
| `written` | 正文已写死 | 完全不动，改动必须走冲突裁决 |

地理的“锚定度 L0–L3”是它在空间维度的具体形式；世界观条目的“被引用次数”、编年史事件的“已写死程度”，都用同一套字段：

```yaml
established:
  level: derived | accepted | written
  evidence: ["第12章 第3段"]
```

### 2.3 校验灯三级 + 永不阻断保存

| 灯 | 含义 | 动作 |
|---|---|---|
| 🔴 | 逻辑矛盾，数据自相矛盾 | 必须裁决（改 A / 改 B / 限定范围） |
| 🟡 | 缺陷：断了因果、缺了表现、留了线头 | 提示，可延后 |
| ⚪ | 提醒：可能故意，也可能是疏漏 | 只列出 |

**唯一例外**：公理层缺“代价”时拒绝保存（铁律一）。其余一律只标灯，不改字。

## 3. 三层七系统

### 3.1 分层

```
设定层（L0–L4）   世界观 · 地理 · 人物/组织 · 编年史 · 事件
                    ↓  产出：一个能演戏的世界
规划层（L5）      篇章结构：卷 / 集 / 章
                    ↓  产出：这一章要干什么
表达层（L6）      场景排演（agent 剧场）+ 成稿
                    ↓  产出：读者读到的字
```

### 3.2 系统总表

| 层 | 系统 | 回答什么 | 核心对象 | 关键机制 | 灯 |
|---|---|---|---|---|---|
| L0 | **世界观** | 什么可能、什么不可能、什么要付代价 | 公理、条目、认知记录 | 公理必须带代价；每条公理 ≥2 表现；myth 允许是假的 | R |
| L1 | **地理** | 世界长什么样、归谁、大事在哪发生 | 区域、奇观、反常、改写 | 关系为真相 → Voronoi 投影成图；反常带梯度与代价；锚定度控制重构 | G |
| L2 | **人物 / 组织** | 谁，要什么，不能做什么，怎么变 | 人物、状态段、组织 | 欲望×底线推出行为；暗线三层真相；伏笔必须双解释 | P |
| L3 | **编年史** | 何时、什么压力、谁怎么看 | 事件真相、压力清单、视角 | 压力编排成节奏；健康度反推上游；真相唯一、记载多种 | C |
| L4 | **事件** | 谁和谁系上了，什么时候被讨 | 故事线、结、张力、余波 | 汇集 → 耦合 → 余波；四类影响；四尺度 | E |
| L5 | **篇章结构** | 这一卷/集/章要干什么 | 卷、集、章、章卡 | 结构单位与事件尺度同构；线必须交叉；章必须具体 | X |
| L6 | **场景排演** | 读者实际读到的每一句话 | 角色 agent、导演 agent、场记 | 角色隔离即信息差；场记为草稿，采纳才回流 | D |

### 3.3 结构层与事件尺度同构

| 结构单位 | 对应事件尺度 | 特征 |
|---|---|---|
| **卷** | 世界事件 | 起因 → 发展 → 高潮 → 结尾 |
| **集** | 地区事件（一个或多个） | **多线并行**，多实体、多视角 |
| **章** | 个人事件（一件或几件小事） | **具体**：发生了什么、说了什么、怎么打的 |
| 场景 | 事件的展开单位 | 四格：目标/障碍/转折/结果 |

**多线叙事不是“作者想切视角”，是同一个世界事件在不同地区、不同人身上的投影必须分别讲。**

```
世界事件：天下第一武道会
   ├─ 地区投影 A：擂台（宗门、旧敌、裁判）      → 线 A
   ├─ 地区投影 B：主办方密室（刺杀密谋）        → 线 B
   ├─ 地区投影 C：城里暗市（押注与消息）        → 线 C
   └─ 个人投影：主角赢了，但漏了底牌           → 章的落点
```

场景（四格）的定义属 L4 的 schema，使用在 L6。

### 3.4 三个阶段的工作台（产品信息架构）

用户眼前不是七个系统，是**三个阶段**。系统是引擎里的东西，阶段是人做事的地方。

| 阶段 | 左栏 | 主区形态 | 这一阶段的产物 |
|---|---|---|---|
| **① 设定** | 世界观 · 地理 · 人物 · 组织 · 编年史 · 事件 | 文档页 / 画布 / 人物卡与关系网 | 一个成立的世界 |
| **② 规划** | 卷 / 集 / 章（结构树） | 上：编年史时间轴（框选）；下：结构树（拖放） | 一份可写的章表 |
| **③ 创作** | 卷/集/章 树 | 本章流水线：章简报 → 场景 → 排演 → 成稿 → 核验 | 读者读到的字 |

三阶段共用一个**对象检查器**（右侧抽屉：字段 / 引用 / 问题）和一个**全局诊断**——因为七个系统共用一张图，任何对象都能被同一套检查器看。

### 3.5 编年史的双重角色

编年史只有一个，是那条时间轴本身，不按阶段拆成两份：

| 阶段 | 角色 |
|---|---|
| 设定 | **产物**：你在写它（含过去与将来，真相与视角） |
| 规划 | **原料**：你在切它（框选成卷、选事件成集、挂事件成章） |

规划阶段对编年史**只选不改**：事件的时间、参与方、真相都是灰的。发现顺序不对，回设定阶段改。

### 3.6 三条通道

| 方向 | 场景 | 行为 |
|---|---|---|
| 向下 | 设定 → 规划 | 公理、地理、人物欲望自动变成编年史的压力 |
| 向下 | 规划 → 创作 | 章卡自动变成创作引擎的简报 |
| 向上 | 创作 → 设定 | 写作中发现缺设定 / 人物不可能这么说 → 就地补，回写上游 |
| 横向 | 任意 | 诊断全局可见，跨系统问题在任何阶段都亮 |

**没有向上通道，这套东西只是“先设计后执行”；有了它，才是工作台。**

## 4. 接口契约

| 系统 | 提供 | 消费 |
|---|---|---|
| 世界观 | `stateAt(year)`、`resolve(id)`、`beliefs(holder)`、`citations(id)` | 母题、类型契约 |
| 地理 | `atlasAt(year)`、`regionsNear(id)`、`siteOf(eventId)` | 自然公理、奇观因果 |
| 人物 | `whoKnows(id)`、`profile(charId, atYear)`、`willDo(charId, situation)` | 阶层、称谓、禁忌、belief |
| 编年史 | `worldState(year)`、`pressures()`、`perspective(eventId, holder)` | 历法、span、势力派生 |
| 事件 | `knots(open)`、`impacts(eventId)`、`scenesOf(eventId)` | cost、四类影响对象 |
| 篇章结构 | `volumes()`、`linesOf(episodeId)`、`chapterBrief(chId)` | 事件尺度与阶段、结、张力 |
| 场景排演 | `transcript(sceneId)`、抽取后的事实变更建议 | 人物语域、认知差、场景四格 |

两个最不起眼但决定成败的：`whoKnows(id)`（谁知道这条设定）与 `citations(id)`（谁在用）。

## 5. 方法论：人怎么用

### 六阶段

| # | 阶段 | 产出 | 通过标准 |
|---|---|---|---|
| 0 | 类型契约 | 允许的解释清单、读者预期、硬边界 | 能回答“怪现象可以被什么解释” |
| 1 | 母题与伤口 | 一句话：世界最根本的缺失 | 能引出至少两条互相冲突的公理 |
| 2 | 公理 | 3–9 条因果源头 | 每条自带代价 |
| 3 | 派生 | 从公理必然推出的结构性后果 | 能解释政治/经济/技术为何长这样 |
| 4 | 表现 | 每条公理 ≥2 个可感知物 | 读者能看见，不是作者知道 |
| 5 | 压力测试 | 一串“为什么不……” | 每个问题都有归属，不许悬空 |

### 三条铁律

1. **没有代价的公理是许愿，不是法则。**
2. **每条公理至少两个可感知表现。**
3. **每个“为什么不”必须落地**（成为条目 / 钩子 / 改公理），不许悬空。

### 四入口一出口

四个入口全部允许：自顶向下（公理推细节）、自底向上（碎片归纳）、人物驱动、情节驱动。
**出口只有一个**：任何进来的设定，最终必须能被某条公理解释，或被登记为“待归约碎片”。

## 6. 建设顺序与理由

```
设定层：世界观 → 地理 → 人物 → 编年史 → 事件
规划层：篇章结构
表达层：场景排演 → 成稿
```

- 世界观最先：它是类型系统与约束源，其余全要读它的公理与历法
- 地理次之：群系与奇观必须能被公理解释
- 人物再次：主角必须被某条公理压到（受益或受损）
- 编年史：需要一张时间表才挂得住事件；与事件长期来回迭代
- 事件：展开编年史，产生结与余波
- 篇章结构：复用事件的尺度与阶段，把“什么发生”排成“第几卷哪一集哪一章”
- 场景排演最后：实际写作层，整套系统的出口

**可用性拐点**：设定层每完成一个系统，工具都能独立交付价值；规划层与表达层必须等设定层可用之后才有意义。所以第一阶段只做世界观。

## 7. 明确不做

| 不做 | 理由 |
|---|---|
| 世界模拟器（自动推演经济/生态/战损） | 无底洞；写小说不需要模拟，需要“提醒你欠了什么” |
| 全自动地图生成 / 全自动世界观生成 | 生成的不是作者想要的那一个；且与“人裁决”冲突 |
| 多用户、云端协作、模板市场 | 自用工具，为通用性付的每一分成本都不划算 |
| 自建版本管理 | 数据是纯文本，`git log` / `git diff` 已经够 |
| 像素/手绘地图 | 地图是关系的投影，不是资产 |
| 独立启动的服务与安装包 | **反转**：DSH 插件只负责启动服务，界面在服务自己的网页上；不做独立安装包 |
| **题材配方**（爽点节奏、打脸债、黄金三章、升级阶梯） | 方法论只回答“结构上必须成立什么”，不回答“怎么让读者爽”。这些进题材扩展包；升级体系只保留一个可选的 `tier` 档位字段（可排序的任意标签），不建系统 |

## 8. 数据与代码分离

```
data/worlds/<worldId>/     ← 作品，纯数据：可拷贝、可 git、工具坏了还在
src/                       ← 代码：engine（纯函数）/ host（路由）/ ui（页面）
```

代码里不存设定，数据里不存逻辑。数据根目录写在插件的 `Config` 里，默认指向工作区的 `data/`。

## 9. 暂不纳入（已记录，不在本期范围）

### 解析 / 测评模式

**想法**：把一本成品小说作为输入，按同一套方法论反解出断言图（断言 + 原文证据 + 置信度），进而：

- 导入旧稿（把已写 20 万字的设定结构化，接着写）
- 拆书报告（节奏曲线、尺度分布、伏笔回收率）
- **测评与权重**：以 N 部高分作品对照低分组，用“区分度”代替主观占比，得出必要维度 / 阈值 / 加分维度，并据此**校准校验规则的严格度**

**为什么暂不做**：

1. **它不是一个系统，是第二个产品。** 七个系统共用一张断言图，靠加边互通；测评需要外部语料库、分组统计与解析流水线。
2. **它依赖设定层全部完工**（解析要跑全套校验、指标要引用各系统字段），却几乎不给核心系统回馈。
3. 若要做，它应当是入口里的第五个（文本驱动），并与正向创作共用同一套 schema，所有解析产物默认 `derived` + 必须带原文证据。

**若将来启动，前置条件**：设定层 P0 全部通过验收；`dimensions.yaml`（维度与指标定义）独立可版本化，同时驱动解析、评分、规则阈值三处。
