> 日期：2026-11-23
> 父文档：`2026-11-23-novel-system-overview.md`

## 1. 定位与边界

**它管**：世界的因果法则、意义系统、历史沉积、时间刻度。
**它不管**：具体地形（地理）、具体的人（人物）、具体发生的事（编年史）。

判断标准：

- “换一个地点还成立吗？” 成立 → 世界观；只在此地成立 → 地理
- “换一个人还成立吗？” 成立 → 世界观/制度；不成立 → 人物卡

**第一版的目标不是“能写设定”，而是“设定可被引用、可被校验”。**

## 2. 方法论

### 六阶段
类型契约 → 母题与伤口 → 公理 → 派生 → 表现 → 压力测试（详见总纲 §5）

### 三条铁律
1. 没有代价的公理是许愿，不是法则
2. 每条公理至少两个可感知表现
3. 每个“为什么不”必须落地，不许悬空

### 运行示例（贯穿本文档）

- 母题：一个靠抽干世界来维持秩序的世界
- 公理：施法会永久烧毁施法者的记忆，烧毁量与法术强度成正比
- 派生：法师阶层无法世袭 → 收养制传承 → 血缘观念被改写
- 表现：还脉礼、欠名录、无字塔、抄名匠、“我记得你”

## 3. 元模型

**只有两种节点、一种边、一种附属记录。**

| 对象 | 是什么 | 例 |
|---|---|---|
| `axiom` | 公理，世界的因果源头 | 施法烧记忆 |
| `entry` | 其余一切：派生、制度、习俗、物件、俗语、职业、生物、信仰 | 还脉礼 |
| `relation` | 六种边 | `derives` `manifests` `requires` `cites` `conflicts` `same_as` |
| `belief` | 认知记录：谁相信什么 | 民间相信玄帝一统天下 |

派生不是独立对象，它就是一条 `entry`，多一条 `derives` 边指向公理。

### 3.1 边

| 边 | 方向 | 用途 | 缺了会怎样 |
|---|---|---|---|
| `derives` | entry → axiom | 从哪条公理来 | 孤儿断言，无从校验 |
| `manifests` | 具体 → 抽象 | 可感知表现 | 设定停在概念层，细节发空 |
| `requires` | entry → 人物/事件/势力 | 谁需要它才成立（跨系统桩） | 人物/情节入口无法接入 |
| `cites` | 正文片段 → entry | 正文在用哪条设定 | 改稿无从查起 |
| `conflicts` | entry ↔ entry | 已知矛盾 + 裁决状态 | 矛盾靠脑子记 |
| `same_as` | entry ↔ entry | 别称、同一实体合并 | 同一物写两条，互相打架 |

**`cites` 用正文里的 `[[双链]]` 表达，不填字段**——写作时顺手标，Obsidian 可直接打开，git diff 可读。

### 3.2 强度四档

| 强度 | 含义 | 例 |
|---|---|---|
| `hard` | 不可违反，违反即世界崩坏 | 施法烧记忆 |
| `firm` | 应该如此但会被人破，破了要留痕迹 | 法师不得为自己施法 |
| `soft` | 地方性、风味性，允许互相打架 | 南方法师戴手套 |
| `myth` | 世界内的说法，**允许是假的** | 玄帝一统天下 |

`myth` 与 `hard` 冲突**不报错**，而是追问：“谁在撒这个谎，他得到什么？”

### 3.3 时间

每个节点都有 `span: { from, to }`（世界内年，`null` = 至今，负数 = 纪元前）。

```
stateAt(612) →
  脉正       在职（412–720）
  记忆当铺   合法经营（588– ）
  还脉礼     已在民间流行（300– ）
  玄帝传说   已流传 300 年，无人质疑
  禁法运动   已失败 40 年，记忆黑市正盛（572– ）
```

版本管理交给 git，不自建。

### 3.4 认知层

```yaml
belief:
  holder: 民间        # 人物 / 势力 / 阶层 / 整个社会 / 读者
  target: W-MY-001
  content: 玄帝曾一统天下，后被众神所罚
  confidence: 0.9
  source: [说书人, 祠庙壁画, 童谣]
  span: { from: 300, to: null }
```

同一真相配不同 holder：民间信（0.9）→ 没人敢挖玄帝陵；教团知道是假的（0.95）→ 教团在**主动维护谎言**；主角从 0.8 改写到 0.1 → **这就是反转，且在数据上是一条记录的变化**。

### 3.5 字段总表（每个字段都要能回答“谁读它”）

| 字段 | 谁读 | 缺了会怎样 |
|---|---|---|
| `id` / `title` / 别名·讳称 | 全体、对话系统 | 引用不了；台词失去称谓质感 |
| `proposition` 命题 | 校验器、AI | 无法判真假、无法查矛盾 |
| `body` 展开 | 人、AI 写作 | 只有骨架，没有质感 |
| `strength` | 校验器 | 不知道哪些能破 |
| `span` | 编年史、事件、时间切片 | 时间上前后错乱 |
| `cost` | 事件系统（代价表） | 情节没有代价可付 |
| `derives` / `manifests` | 校验器、检视 | 孤儿断言、细节发空 |
| `cites` | 改稿、检索 | 改一处崩一片 |
| `belief` | 人物、对话、反转 | 所有人都知道真相，没有潜台词 |

### 3.6 历法必须是数据

```yaml
calendar:
  epochs:
    - { name: 旧世, start: -1200, end: -1 }
    - { name: 新历, start: 1, end: null }
  format: "新历{year}年"
  months: [霜月, 雨月, 芽月, ...]
```

写成散文（“天下分九州，岁在甲子”）则排序、挂事件、时间切片全部做不了。

## 4. 视图

### 4.1 入口只有两个框

```
标题  还脉礼
内容  法师临终前，亲属替他把一生施过的法逐条念出，算是替他还债。
      念的人不能是法师自己——他记不住。
                                                    [ 保存 ]
```

保存后其余字段才出现，且**全部有默认值、默认收起**：

| 字段 | 默认 | 何时会碰 |
|---|---|---|
| 强度 | `soft` | 校验器咬到时 |
| 生效区间 | 至今（from 留空） | 要写“已失传”时 |
| 类型 | 由标题与内容猜 | 猜错才改 |
| 代价 | 空 | **仅公理必填** |

只有公理被强制——强制只加在最该强制的地方。

### 4.2 命题：AI 起草，人随手改

```
还脉礼
  亲属替临终法师逐条念出其一生所施之法，以偿其债。   ✎
   [ 不像我说的 · 重新归纳 ]
```

若 AI 归纳不出“可判真假”的句子（例如“南方的法师很有特色”），直接提示：

> 这条设定现在还不可校验。要么补一个具体做法，要么补一个边界。

### 4.3 四视图

| 视图 | 干什么 | 关键 |
|---|---|---|
| **条目页** | 写的地方，90% 时间在这 | 右侧抽屉收起其余字段 |
| **卡片墙** | 找的地方 | 角标：未被引用 / 无公理支撑 / 有未决矛盾 |
| **诊断清单** | 查的地方 | **P0 不做力导向图谱**，用清单；节点过 300 再考虑 |
| **时间轴** | 对时间的地方 | 竖线切过 = 那一年的世界；同时是编年史雏形 |

诊断清单样式：

```
无公理支撑（3）
  · 脉正            → [指定公理] [标记为设定装饰]
未被正文引用（7）
  · 还脉礼 · 无字塔 · 抄名匠 …
未决矛盾（1）
  · 「禁法运动失败」 vs 「教团明令禁止施法」   [裁决]
待归约碎片（4）
  · “南方法师戴手套” “童谣：九脉三枯”
```

### 4.4 最省力的录入路径

- **从正文反向长设定**：选中一句话 → `[存为设定]` → 建条目 + 建 `cites` 边
- **未定义专名扫描**：正文里出现无对应条目的专名 → 标红 → 一键建条目

### 4.5 AI 只出现在三个按钮上

| 按钮 | 在哪 | 产出 | 绝不产出 |
|---|---|---|---|
| 归纳 | 条目页命题行 | 一句可校验命题 | 不写正文 |
| 审问 | 条目页 / 诊断清单 | “为什么不……”问题清单 | **不产出设定** |
| 裁决建议 | 矛盾条目 | 三种解法 | 不替你选 |

### 4.6 三步开局（不可跳过）

```
① 这个世界最根本的缺失是什么？（一句话）
② 给它 3 条公理。每条必须付出代价。
③ 每条公理，至少两个“能看见的东西”。
```

## 5. 校验规则（R1–R12）

| # | 触发 | 灯 | 提示与动作 |
|---|---|---|---|
| R1 | 两条 `hard` 逻辑互斥 | 🔴 | 三选一裁决 |
| R2 | `firm` 写了“有人违反”但无后果节点 | 🟡 | 补后果，或降级为 soft |
| R3 | `myth` 与 `hard` 冲突 | ⚪ | 不报错，生成“谁在撒谎”追问 |
| R4 | 条目既无 `derives` 也无 `requires` | 🟡 | 指定公理 / 标为设定装饰 |
| R5 | 条目无任何 `cites` | ⚪ | 从未进入正文，要么用要么删 |
| R6 | 同一实体在重叠时间有两个互斥版本 | 🔴 | — |
| R7 | **公理 `span` 不覆盖依赖它的条目 `span`** | 🔴 | 派生链断裂（大时间尺度错误） |
| R8 | 两节点疑似同一物但未合并 | 🟡 | 建议 `same_as` |
| R9 | 某 holder 的 belief 与 `hard` 冲突且置信 > 0.8 | ⚪ | 是设定的误解，还是写漏了 |
| R10 | `body` < 20 字且无 `manifests` | 🟡 | 只有标题 |
| R11 | 公理少于 3 条 | ⚪ | 仅开局阶段出现 |
| R12 | 某公理 `manifests` < 2 | 🟡 | 铁律二 |

**R7 是最值钱的一条**：抓“七百年前法则变了，却忘了改依赖它的三条制度”。

### 冲突裁决：第三种解法最重要

改 A / 改 B / **两条都成立，因为分属不同地区或不同时间段**。
多数所谓矛盾其实是“没限定范围”。选第三种时系统自动加地域限定或 `span`，矛盾消失且世界变厚。

### 运行时机

- 保存一条：只跑相关规则（R1/R6/R7/R10/R12），毫秒级
- 打开诊断清单：全量 + 跨节点
- 审问：手动触发

## 6. 存储

```
worlds/记忆之世/
  world.yaml                 # 类型契约、历法、母题
  nodes/记忆即燃料.md         # YAML front matter + 正文，一条一文件
  nodes/还脉礼.md
  beliefs/玄帝传说.yaml
  fragments/第03章-02.md      # 片段库
  index.json                 # 派生索引（引用图），可重建，不进 git
```

节点示例：

```markdown
---
kind: axiom
id: W-AX-002
title: 记忆即燃料
strength: hard
span: { from: -1200, to: null }
proposition: 施法会永久烧毁施法者的记忆，烧毁量与法术强度成正比
cost: [记忆, 身份, 亲情]
---

施法会永久烧毁施法者的记忆，烧毁量与法术强度成正比。

这条规则不是秘密，是常识——就像我们知道火会烫手。
```

片段示例：

```markdown
---
chapter: 3
scene: 2
---
他把袖子往上捋了捋，[[欠名录]]上又多了三个名字。
「[[玄帝]]断三脉那年，[[脉正]]换到第九任了。」老人说。
```

**数据是唯一真相，索引是派生物。** 删掉 `index.json` 可自动重建。

## 7. 代码结构

```
src/
├── engine/            # 纯函数，不碰文件与网络，可单测
│   ├── schema.ts      类型与字段合法性
│   ├── graph.ts       建图、反推入边、孤儿检测
│   ├── rules/         一条规则一个文件
│   │   ├── r01_hard_conflict.ts
│   │   └── r07_span_break.ts
│   ├── query.ts       stateAt / beliefs / citations
│   └── resolve.ts     [[双链]] 解析
├── server/            # fs 读写 + HTTP
└── ui/                # 浏览器界面
```

引擎不依赖 server 与 ui，因此可命令行运行：`ops check 记忆之世`。

## 9. 验收测试（写进 spec，不是口号）

1. **半小时造世界**：从零到 5 条公理 + 20 条条目 + 3 段片段，全程不碰 JSON、不开文件管理器
2. **故意埋雷**：制造一条 `hard × hard` 矛盾，诊断清单能同时定位两条并给三种解法
3. **时间断层**：截断某公理的 `span`，依赖它的条目立刻亮红灯（R7）
4. **删除保护**：删一条被正文引用的条目时被阻止并列出引用处
